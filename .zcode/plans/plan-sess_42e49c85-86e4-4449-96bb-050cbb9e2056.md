# TNR 系统全面测试与优化计划

**目标仓库**：`https://cnb.cool/tnrxy/TNR.git`（main，最新 `7a77622`），克隆到工作目录 `/Users/wl/M4/TNR`（当前为空）。
**项目**：流浪动物 TNR 管理系统（Django 5 + DRF 全栈，四角色门户 + 公开领养大厅，自研"水墨丹青"样式）。现状全仓库零测试，新测试从零编写。

## 阶段 0：拉取代码与环境搭建
1. `git clone https://cnb.cool/tnrxy/TNR.git /Users/wl/M4/TNR`（钥匙串已有 cnb 凭证，若失效改用所提供 token），校验 HEAD 为 cnb/main 最新。
2. `python3.12 -m venv .venv` → `pip install -r requirements.txt` → `cp .env.example .env`（SQLite 开发库）→ `migrate` → `seed_data` → `runserver` 冒烟验证。
3. 通读 spec 文档与各 app 的 urls/models/services，产出「功能—路由」覆盖清单作为测试依据。

## 阶段 1：编写全新自动化测试（Django 内置框架，不引入新依赖）
按 app 组织 `tests/` 包，覆盖：
- **accounts**：登录、按角色重定向、5 角色 RBAC 权限矩阵、`@role_required`。
- **core**：区县/机构模型与约束。
- **business**：编号生成规则；物料双台账（入库/下发/签收/消耗/异动）；芯片唯一不可复用；黑名单拦截；区县数据隔离；各业务 API（捕捉登记、主人领回、转运拆分/签收/驳回、诊疗四项与库存联动、放养确认、领养登记/领出、大厅上架、回访打卡审核、安乐死、消息）；全生命周期集成链路（捕捉→转运→诊疗→自动转待领养→放养→领养→回访→溯源接口）。
- **supervision**：政府端接口权限、大屏统计、系统配置、操作日志。
- 运行 `python manage.py test`，对发现的 bug 做最小化修复并回归。

## 阶段 2：浏览器全流程走查（GUI 黑盒）
用种子数据以四类角色真实走查核心页面与操作（登录→各端工作台→核心表单→领养大厅），截图记录 bug / 交互 / 美观问题，分级汇总成清单。

## 阶段 3：优化实施（保守幅度，保持水墨丹青风格）
- **使用方便、操作简便**：表单默认值与校验提示、步骤引导、常用入口、批量操作。
- **逻辑通顺**：状态流转提示、通知触达、页面跳转闭环。
- **界面美观**：按钮/表格/徽标/弹窗样式统一、间距排版、空状态与加载态、响应式。
- 每批优化后全量测试回归 + 浏览器复验。
